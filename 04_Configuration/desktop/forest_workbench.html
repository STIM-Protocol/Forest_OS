⚡ Practical Field Execution Pipelines

Production tested, multi-tier workflows combining host CLI, native GIS, and container engines.

🌲 Pipeline 1: Aerial UAV Imagery to Individual Tree Crowns

Ingest raw drone orthomosaics, detect individual crowns via PyTorch deep learning, and produce vector polygons for GIS analysis.

  • Input: Georeferenced GeoTIFF orthomosaic (RGB or Multispectral)
  • Engine: DeepForest (Tier 1 uv CLI tool)
  • Output: Shapefile / GeoPackage with bounding boxes and detection confidence
# Step 1: Run DeepForest prediction on field drone orthomosaic deepforest --input plot_orthomosaic.tif --output detected_crowns.shp --patch-size 400 # Step 2: Open in QGIS to review canopy delineation qgis detected_crowns.shp plot_orthomosaic.tif

🛰️ Pipeline 2: Airborne LiDAR to Canopy Height Model & Tree Isolation

Process classified LAS/LAZ point clouds, generate normalized digital surface models, and segment single trees with watershed filters.

  • Input: Raw or classified airborne LiDAR point cloud (.laz)
  • Engine: forest-r container sidecar (lidR + ForestTools)
  • Output: Canopy Height Model (CHM raster) and individual tree treetops/crowns
# Execute headless LiDAR normalization and tree segmentation via container forest-r -e ' library(lidR) library(ForestTools) las <- readLAS("stand_data.laz") nlas <- normalize_height(las, tin()) chm <- rasterize_canopy(nlas, res = 0.5, pitfree()) ttops <- vwf(chm, winFun = function(x){x * 0.06 + 0.5}, minHgt = 2) writeLAS(nlas, "stand_normalized.laz") '

🎙️ Pipeline 3: Autonomous Canopy Bioacoustics Survey

Batch process long duration AudioMoth or Song Meter recordings from forest plots to establish avian biodiversity baselines.

  • Input: Directory of WAV field recordings
  • Engine: BirdNET-Analyzer (Tier 1 uv tool)
  • Output: CSV detection records with species names, timestamps, and confidence scores
# Analyze entire audio survey directory with 70% confidence threshold birdnet-analyze --i audio_survey/ --o results/ --min_conf 0.70 --threads 4 # Or launch the interactive GUI for visual spectrogram auditing birdnet-gui

🪵 Pipeline 4: Tree-Ring Core Cross-Dating & Climate Calibration

Measure tree increment cores, cross-date samples across stands, detrend age growth signals, and correlate with climate indices.

  • Input: High resolution core scan or Tucson (.rwl) measurement series
  • Engines: pyDendron (GUI) + dplR / treeclim (forest-r container)
  • Output: Master stand chronology and monthly climate correlation coefficients
# Launch pyDendron for interactive core ring measurement pyDendron # Run standardized cross-dating statistics in containerized dplR forest-r -e ' library(dplR) series <- read.rwl("cores.rwl") stats <- rwl.stats(series) crn <- chron(series, prefix = "FOR") plot(crn) '

📈 Pipeline 5: Silvicultural Growth Simulation & 40-Year Yield Projection

Run individual-tree growth projections under alternative harvest and thinning scenarios using USFS Open-FVS.

  • Input: Forest inventory plot tree lists and site parameters
  • Engine: forest-sim container sidecar (compiled regional FVS variants)
  • Output: Volume yield tables, mortality curves, and stand structure forecasts
# Inspect all 22 available USFS regional FVS variants forest-sim variants # Run Pacific Northwest variant on field keyword deck forest-sim run FVSpn stand_scenario.key # Or start the local REST microservice on port 8000 forest-sim serve

The Three-Tier Zero-Bloat System Strategy

Forest OS avoids package drift and dependency hell by enforcing strict boundaries across runtimes:

Tier 1: Host User-Space CLI

Installed via uv tool install --python 3.11 <pkg> into isolated virtual environments with symlinks in ~/.local/bin/. Never modifies system Python.

  • DeepForest (Canopy Crown AI)
  • BirdNET-Analyzer (Acoustic Detection)
  • dplPy (Dendrochronology)
  • pyfia (USFS FIA Analysis)

Tier 2: Native Distro GIS / GUI

High performance C++ and Qt desktop applications installed via Ubuntu APT or Arch Pacman for full Wayland and GPU hardware acceleration.

  • QGIS (Geographic Information System)
  • GDAL & PDAL (Spatial Raster & Point Cloud CLI)
  • CloudCompare (3D Mesh & Cloud Processing)
  • pyDendron (Tree Ring Measurement GUI)

Tier 3: Scientific Container Engines

Complex R-spatial stacks and Fortran simulation suites packaged in Docker/Podman sidecars. Execute via CLI wrappers mounting current working directories.

  • forest-r-engine (lidR, TreeLS, rGEDI, BIOMASS)
  • forest-sim (Open-FVS 22 regional variants, microfvs)
  • forest-odm (WebODM drone photogrammetry)
