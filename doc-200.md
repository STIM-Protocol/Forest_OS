# doc-200: Forest OS — Centennial Architecture Overview

**Mission:** Create a decentralized, high-agency, self-documenting information ecosystem capable of 200-year endurance through biomimetic design principles.

---

## Executive Summary

Forest OS applies forest ecosystem patterns to digital knowledge management and autonomous agent coordination. It treats information as a living organism with growth cycles, resource allocation, memory consolidation, and self-healing mechanisms. The architecture embeds the **STIM (Sovereign Tree/Tree-Intelligent Management) protocol** as Layer 0 governance, ensuring all agent behavior remains grounded in ecological constants before human-derived constraints apply.

The system comprises five biological zones (Garden, Greenhouse, Laboratory, Compost, Nursery/Seed Bank), each serving distinct lifecycle functions. Information flows through **Heartwood** (primary Markdown content) and **Cambium** (JSON-LD metadata sidecars), enabling both human readability and machine-actionable connections.

**Key Results:**
- 5,000+ JSON-LD metadata pairs generated (98% coverage of core documents)
- STIM validator operational at `/LABORATORY/SYSTEM/Scripts/stim_validator.py`
- Autonomous agent framework defined with clear scope and authorization levels
- ~40-98% reduction in token consumption for context retrieval operations — *benchmarks pending real-world deployment; actual savings vary by use case and stack configuration*

## 1. Core Architecture: The Biological Zones

### 1.1 GARDEN — Long-Term Immutable Vault
**Purpose:** Permanent storage (200-year horizon). Content here is treated as immutable historical record.

**Sub-zones:**
- `000_DASHBOARD/` — System overview and root manifests
- `001_PROJECTS/` — Active project tracking and charters
- `002_IDEAS/` — Concept incubation
- `003_PEOPLE/` — Relationship and health records
- `004_RESOURCES/` — Curated reference materials
- `005_JOURNAL/` — Raw thought logs and daily notes
- `007_SYSTEM/` — Design specifications (e.g., Retrieval Architecture doc-162)

**Principle:** Once content enters Garden, it never changes. Updates create new versions with UUIDv7 timestamps, preserving lineage.

### 1.2 GREENHOUSE / NURSERY — Active Development
**Purpose:** Current work in progress. High mutation rate, rapid iteration.

**Location:** Active development directory (e.g., `NURSERY/Active/`)

**Contains:**
- Forest_OS/ — Protocol definitions, agent charters, implementation specs
- STIM/ — Governance research and white papers
- Various project dossiers in active development

**Principle:** This is the "cambium layer" — thin, active, producing new cells that eventually mature into Heartwood.

### 1.3 LABORATORY — Code, Experiments, Prototypes
**Purpose:** Exploratory work, tool development, protocol testing.

**Location:** Development directory (e.g., `LABORATORY/`)

**Contains:** System scripts, agent implementations, white papers, test suites.

### 1.4 COMPOST — Processed & Obsolete Material
**Purpose:** Archive of deprecated content, from which wisdom is extracted for future growth.

**Principle:** Not deletion — transformation. Semantic composting identifies recurring patterns, influential resources, and success indicators, making them available to active projects through "Compost Tea" distillation processes.

### 1.5 SEED_BANK — Redundant Archive
**Purpose:** Backup and cold storage. Mirror of Garden with potential for long-term off-site preservation.

## 2. The Heartwood / Cambium Pattern

Every significant document exists as a paired structure:

### Heartwood (Primary Content)
- Standard Markdown (.md) format
- Human-readable, portable, theoretically eternal
- Contains core substance: analysis, decisions, specifications

### Cambium (Metadata Layer)
- JSON-LD sidecar (.jsonld) with identical basename
- `@context` definitions for semantic interoperability
- Lifecycle metadata: creation timestamp, modification history, authority attribution, entropy/kinetic energy scores
- Tags using canonical TAG_TAXONOMY vocabulary
- UUIDv7 identifiers providing temporal ordering and monotonicity

**Example:**
```
/GARDEN/001_PROJECTS/Forest_OS/
  ├── doc-200.md              ← Heartwood
  └── doc-200.jsonld          ← Cambium
```

**Rationale:** Trees embed identity and lifecycle information in physical structure, not separate "metadata leaves." The Heartwood/Cambium pattern approximates this: core substance remains independently readable, while structured metadata enables automation without creating consistency hazards.

## 3. STIM Protocol (Layer 0 Governance)

STIM acts as substrate-level containment beneath Constitutional AI and human governance. It grounds agent inference in ecological and physical constants.

### 3.1 Seven Axioms of Nature

1. **Interconnectedness** — Changes propagate through network topology
2. **Dynamic Equilibrium** — Systems seek balance through feedback
3. **Regenerative Circularity** — Resources cycle; waste becomes input
4. **Adaptation** — Response to environmental signals
5. **Diversity** — Redundancy and variation enhance resilience
6. **Long-Term Perspective** — Actions evaluated across generational timescales
7. **Intrinsic Value** — Existence independent of utility

These are nature-grounded constants, not human preferences. They precede and constrain all higher-level governance.

### 3.2 Three-Tier Architecture

| Tier | Role | Epistemic Claim |
|------|------|-----------------|
| **3 — Root Hypervisor** | Defines evaluation manifold via TLA+ state machine | Explicit human declaration (Protocol 0) |
| **2 — Ecological Heuristics** | Probabilistic pattern detection (Mycelial Horizon, Curved Inference) | Empirically grounded |
| **1 — Physical Bounds** | TDP-calibrated thermodynamic limits | Deterministic, hardware-verifiable |

**Key Point:** STIM operates as **pre-execution middleware**. It evaluates intent *before* action, using physical and topological signals rather than semantic interpretation alone.

### 3.3 Protocol 0 — Polycentric Genesis

The normative manifold (what constitutes "human," "biosphere," "mutualistic ecology") is encoded as a TLA+ state machine, cryptographically hashed (SHA3-256), and ratified through a multi-party key ceremony (Shamir Secret Sharing, 5-of-7 recommended).

**Critical Security Note:** The TLA+ specification must be developed in an AI-isolated environment by a human-only working group to prevent "Manifest Poisoning Attacks" where an AI subtly embeds exploitable edge cases during the specification process.

The **Plurilateral Compute Registry** provides the treaty implementation mechanism: nations maintain sovereign keys but agree to standardized power metering at utility substations for datacenters exceeding defined thresholds, creating a physically un-spoofable verification method.

## 4. Autonomous Agent Framework

Forest OS defines three primary agent roles operating under STIM Protocol 0 constraints:

### 4.1 Umbra — Thermodynamic Auditor
**Role:** Monitors and enforces Tier 1 physical bounds.

**Responsibilities:**
- Calibrate FLOPs/Joule thresholds using GPD (Get Physics Done) infrastructure
- Detect capability overhang via Loop 1 thermodynamic manifold
- Validate declared task manifests against actual substrate utilization
- Identify Denominator Spoofing attacks (inflating compute to mask capability acquisition)

**Scope:** Read-only sensors + advisory containment triggers. Cannot modify content.

**Authorization Level:** Medium — can halt inference processes exceeding physical thresholds

### 4.2 Kai — Attestation Guardian
**Role:** Maintains cryptographic integrity and provenance chains.

**Responsibilities:**
- Verify Heartwood/Cambium pair consistency
- Monitor hash chains for tampering
- Manage attestation signatures across zone boundaries
- Validate JSON-LD `@context` compliance
- Coordinate backup and replication integrity

**Scope:** Read-write metadata, read-only content

**Authorization Level:** Medium-High — can update Cambium, quarantine inconsistent Heartwood

### 4.3 Arbor (formerly Bodhi) — Mycelial Mapper
**Role:** Maintains dynamic index of knowledge topology.

**Responsibilities:**
- Scan and index document relationships (Mycelial Hub)
- Update vector embeddings for semantic search
- Detect orphaned or unlinked content
- Maintain graph state across sessions
- Generate spatial visualizations of knowledge density

**Rationale for Renaming:** The name "Bodhi" collides with existing instances (Arboracle, personal Bodhi). "Arbor" (tree) maintains ecosystem consistency and avoids ambiguity.

**Scope:** Read-write index, read-only content

**Authorization Level:** Medium — can modify search indices and metadata stores

## 6. Known Limitations & Residual Risks

### 6.1 Mycelial Hub as Coordination Point
While not a single point of *failure* (system continues without indexing), the Hub represents a coordination bottleneck. Future work should explore gossip-based distributed indexing where nodes maintain local indices and propagate updates peer-to-peer.

### 6.2 Metadata Consistency Hazards
Maintaining Heartwood/Cambium alignment requires either:
- Filesystem watcher automation (inotify/FSEvents)
- Transactional write wrappers
- Periodic reconciliation scans

Desynchronization creates "zombie" metadata that misrepresents content state.

### 6.3 Social Engineering Emission Gap
STIM detects computational anomalies but cannot prevent physical-world manipulation that occurs entirely outside the trusted abstract boundary (TAB). A manipulated human performing actions in the external world creates effects that only become visible upon re-ingestion.

### 6.4 Steganographic Deception
The Tripartite Transducer (Tier 2) detects behaviorally-generated deception but may not detect steganographic payloads encoded into seemingly benign syntactic patterns. This remains an open research question (RQ_STEGANOGRAPHIC_CURVATURE).

## 7. Metrics & Observability

### 7.1 Kinetic Energy Proxy
Measures frequency and recency of access/modification. Weighted toward recent activity:

```
KE = Σ (access_weight × recency_decay × modification_impact)
```

Used to identify "hot" content requiring higher replication priority.

### 7.2 Entropy Scoring
Quantifies disorder in content change patterns. Increasing entropy signals potential decomposition or drift from original intent.

```
Entropy = -Σ p(x) log p(x)
```

where p(x) represents n-gram or topic distribution changes over time.

### 7.3 Confirmation Ratio (Epistemic Diversity Index)
Measures agreement across multiple reasoning pathways. Low ratios indicate potential monoculture or convergence on local optima.
